# Hogwarts Academy — TypeScript Mini Project

A small terminal project to practice:

- Generics and generic constraints
- Utility types: `Pick`, `Omit`, `Partial`, `Record`, `Parameters`, `ReturnType`, `Extract`, `Exclude`
- Conditional types and `infer`
- Index signatures
- Type guards and discriminated unions
- Legacy TypeScript method decorators (`target`, `propertyKey`, `descriptor`)

## Requirements

- Node.js 18+ recommended
- npm

## Setup

```bash
npm install
```

## Run

```bash
npm start
```

## Type-check

```bash
npm run typecheck
```

## Project structure

```
src/
├── types/          types only (wizard, spell, events, utility)
├── guards/         type guards (isHouse, isWizard)
├── decorators/     Log, MeasureTime, ValidateSpellPower, Cache
├── repositories/   generic Repository<T>, WizardRepository, SpellRepository
├── services/       AcademyService, SpellCalculator
├── handlers/       handleSpellCast
├── demos/          demo scenarios for each exercise
└── main.ts         composition root only
```

## Design decisions (SOLID)

- **Single Responsibility Principle**: one file, one responsibility. `main.ts` only wires the objects together and runs the demos. Wizard ids are generated by the repository, not by the caller.
- **Open/Closed Principle**: `Repository<T>` is never modified. Logging, timing, validation and caching are added through decorators, and `SpellRepository` extends the base class to add spell power validation.
- **Type safety**: `NewWizard` is built so that `Omit` keeps working with the index signature of `Wizard`, `SpellCastEvent` is derived with `Extract`, and `isHouse` accepts only the four valid houses.

## Note about decorators

This project intentionally uses the legacy TypeScript decorator API so you can learn the three method-decorator arguments:
`target`, `propertyKey`, and `descriptor`. The project enables `experimentalDecorators` in `tsconfig.json`.
